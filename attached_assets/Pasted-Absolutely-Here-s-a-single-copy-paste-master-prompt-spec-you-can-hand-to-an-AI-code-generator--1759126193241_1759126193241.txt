# Build Prompt — “VectorWiz Portal” (Next.js full-stack app under `/portal`)

You are building a production-grade full-stack web app that runs under the **/portal** subdirectory of an existing WordPress site (same domain). The app must ship an MVP containing **Ordering**, **Client Portal**, and **Tools** and be search-friendly where appropriate.

## 0) High-level goals

* Preserve all current WP marketing URLs.
* Serve the app at `https://vectorwiz.com/portal/*`.
* Server-render SEO-indexable pages for tools (NOT client/account).
* Clean, human-powered vector-service positioning; collect orders, payments, files; manage proofs/revisions; deliver assets.

## 1) Architecture

* **Routing:**

  * `/*` → WordPress (existing host)
  * `/portal/*` and `/api/*` → Next.js (Node, Vercel) via **reverse proxy**
* **Reverse proxy** (choose one):

### Cloudflare (preferred)

* Route: `example.com/portal/*` → Vercel Next.js origin
* Cache rules: bypass for `/portal/api/*`, static cache for `/portal/_next/static/*`
* Set `X-Forwarded-Host` so Next.js generates canonical URLs under `/portal`.

### Nginx snippet

```nginx
location /portal/ {
  proxy_pass https://NEXT_ORIGIN;  # e.g. Vercel or Node host
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
location /api/ {
  proxy_pass https://NEXT_ORIGIN;
}
```

* **Stack:** Next.js 14 (App Router) + TypeScript + Tailwind + shadcn/ui
* **API:** Next.js Route Handlers (REST) + Zod validation
* **DB:** **PostgreSQL (Neon)** + Prisma
* **Auth:** JWT (httpOnly cookies + refresh tokens) with RBAC
* **Payments:** Stripe (Checkout + Invoices)
* **Storage:** Cloudflare R2 or S3 for uploads; signed URLs; ClamAV scan
* **Email:** Postmark (transactional)
* **Observability:** Sentry + basic audit log table
* **Search/Indexing:** Algolia/Meilisearch (optional; v2)

```prisma
model User {
```

## 5) Auth (JWT, no 3rd-party IdP)

* **Credentials login** (email + password) → issue **access token** (15m) and **refresh token** (30d) via httpOnly, Secure cookies scoped to `.vectorwiz.com` and **path=/portal**.
* **Refresh** endpoint rotates refresh token (store JTI in `Session`).
* **Middleware** protects `/portal/(account)/**` and `/portal/api/**` (except auth/file presign/stripe webhooks).
* **RBAC:** Guard admin routes (`/portal/api/admin/**`) for `ADMIN`; designers can update orders and upload proofs.

## 6) Core features (MVP)

### A) Ordering (public → checkout → account)

* **Order Wizard (/portal/order)**:
  Steps: Choose service → Upload files (drag-drop to R2/S3 via presigned) → Describe requirements (color matching, formats: AI/EPS/SVG/PDF/DXF) → Get estimated price range → Create order → Pay with Stripe Checkout (or request invoice).
* **API contracts**

  * `POST /api/orders` → {service, notes, fileKeys[]} → {orderId, status, priceEstimate}
  * `POST /api/payments/checkout` → {orderId} → {checkoutUrl}
  * `GET /api/orders/:id` → order details (user-scoped)
* **Pricing**: return **estimate** (simple heuristic by file count + size + declared complexity). Final price set by admin; if price changes post-review, send payment link.

### B) Client Portal (authenticated)

* **Dashboard**: list orders, statuses, unread messages, invoices, downloads.
* **Order detail**: timeline, messages (threaded), proofs (approve/request changes), final files.
* **Files**: show source uploads & final deliverables; download with **signed URLs**.
* **Invoices**: Stripe invoices + receipts.
* **Messages**: simple 2-way messaging (email notifications to both sides).

### C) Tools (indexable)

* `/portal/tools/dpi-calculator` — compute print DPI & size; surface “needs vector” result + CTA.
* `/portal/tools/turnaround-estimator` — ETA based on service & queue.
* `/portal/tools/vector-checker` — upload small image; if raster, suggest order.
* **All tool pages are SSR, have canonical URLs, and include JSON-LD (`SoftwareApplication` + `FAQPage` where relevant).**

## 7) Payments

* **Stripe Checkout** session per order; webhooks set order status `WAITING_PAYMENT` → `IN_PROGRESS` when paid; generate **Invoice** record; send Postmark email to customer.
* Support **draft invoice** flow for admin-priced jobs.

## 8) Storage & file pipeline

* **Uploads**: client requests `POST /api/files/presign` → returns PUT URL + key.
* After upload completes, client calls `POST /api/files/complete` (or set by webhook) → queue antivirus scan → on success attach file to order & mark `SOURCE/UPLOAD`.
* Proofs and finals stored with `PROOF`/`FINAL` kinds.
* Signed GET URLs expire in 5 minutes.

## 9) SEO & indexation rules

* **Indexable**: `/portal/tools/*` and `/portal` landing (light).
* **Noindex**: `/portal/order`, `/portal/(account)/**`, `/portal/api/**`.
* `sitemap.ts` should include only tools pages; WP keeps its own sitemaps. Add a merged parent sitemap in WP later.
* Add schema to tools pages; add `Organization` to `/portal`.

**robots.ts**

```ts
export default function robots() {
  return {
    rules: [
      { userAgent: '*', allow: ['/portal/tools/'], disallow: ['/portal/api/', '/portal/order', '/portal/account'] },
    ],
    sitemap: 'https://vectorwiz.com/portal/sitemap.xml'
  };
}
```

## 11) Security

* httpOnly, Secure cookies; SameSite=Lax.
* CSRF: use double-submit token on POST forms for logged-in pages.
* Rate-limit `/api/auth/login`, `/api/orders`.
* Validate all inputs with **Zod**; sanitize filenames; virus scan uploads.
* Audit log table (who changed what & when on orders).

## 12) Analytics

* Server logs to Sentry; add request IDs.
